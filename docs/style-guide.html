01 · Fundamentos

Cores

Todas as cores base ficam em src/styles/tokens.css como variáveis CSS. Nunca usar hex direto em componentes reutilizáveis — sempre var(--nome-do-token). Isso é o que permite corrigir contraste ou tema em um único lugar e propagar para o app inteiro.

Regra de contraste: todo texto precisa de no mínimo 4.5:1 de contraste contra o fundo real (WCAG AA). Cuidado com dois erros já cometidos neste projeto: (1) aplicar opacity num texto que já tinha cor correta — a opacidade mistura com o fundo e derruba o contraste calculado; (2) usar a cor da marca como texto sobre um fundo colorido claro (ex: badge, link ativo) — nesse caso use --cor-primaria-texto, não --cor-primaria.

Modo escuro

O dark mode redefine as mesmas variáveis dentro de body.dark-mode — os componentes não sabem que o tema mudou, só o valor da variável muda.

body.dark-mode {
  --cor-fundo: #0f172a;
  --cor-painel: #1e293b;
  --cor-texto-principal: #f8fafc;
  --cor-texto-secundario: #cbd5e1;
  --cor-borda: #334155;
}

02 · Componentes

Formulários

Padrão base em .form-group (components.css). Todo <label> deve ter htmlFor apontando pro id do campo — isso já foi motivo de correção de acessibilidade neste projeto (labels visuais sem associação real ao input).

CPF inválido — informe os 11 dígitos.

Chips e toggle-cards

Via pública ✓ Rodovia 
<div className="form-group">
  <label htmlFor="data_ocorrencia">Data da Ocorrência *</label>
  <input type="date" id="data_ocorrencia" value={...} onChange={...} />
</div>

Checklist de acessibilidade ao criar um formulário novo

  • Todo <label> tem htmlFor = id do campo (campos repetidos em lista: gerar id único com o uid do item)
  • Botões só-ícone têm aria-label (fechar modal, remover item, buscar)
  • <select> sem label visível tem aria-label
  • Headings seguem ordem sequencial (h1→h2→h3...) mesmo quando conteúdo é condicional/por passo
  • Contraste de texto ≥ 4.5:1 — não usar opacity pra "suavizar" texto, usar uma cor com contraste já calculado

Convenções para alterações futuras

Onde mexer em cada coisa

ArquivoContém

Antes de adicionar uma cor nova

  • Já existe um token parecido em tokens.css? Reaproveitar em vez de criar outro hex
  • Calcular contraste contra o fundo real onde o texto vai aparecer (não contra branco por padrão — cards coloridos, badges e sidebar têm fundos diferentes)
  • Se for variante "texto sobre fundo tingido" (ex: badge, link ativo), considerar um token -texto dedicado em vez de reusar a cor de marca/ícone direto (ver --cor-primaria-texto)
  • Definir também o valor equivalente em body.dark-mode

Antes de abrir um PR de UI

  • npm run build local sem erros
  • Rodar Lighthouse (aba Accessibility) na página alterada, em todos os passos/estados relevantes (não só o estado inicial)
  • Conferir modo claro e escuro
  • Se mexeu em tokens.css ou components.css: o efeito é global — checar outras páginas que usam a mesma classe/variável
